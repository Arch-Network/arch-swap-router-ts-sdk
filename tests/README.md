# Tests

`accounts/pda.test.ts` verifies SDK-delegated ATA and vault/reserve/escrow PDA
derivation against the Rust router's `tests/account_validation.rs` fixtures.
It also checks malformed public keys and leading zero bytes in base58 decoding.

`codecs/instruction.test.ts` and `codecs/result.test.ts` verify instruction bytes
and result framing using 31 instruction and 12 result fixtures generated by a
standalone Rust program. They also cover invalid integer ranges and types, step
counts, CLAMM direction/supplement fields, all truncated result lengths,
unsupported versions, and byte views with nonzero offsets. See
[fixture provenance and regeneration](fixtures/router-codec/README.md).

The result decoder checks framing only. Receipt success, rollback status, and
publisher identity checks remain checkpoint 8 work. Codecs remain internal until
the planned receipt exports are implemented.

`transactions/instructions.test.ts` and `transactions/size.test.ts` verify
complete instruction bundles against 18 fixtures generated using Rust's native
Arch PDA derivation and message compilation. They cover all initial directed
paths, duplicate fee/tick positions, account privileges, supplemental counts,
the 1,211/1,275-byte three-hop cases, the exact size limit, signature counts,
and compilation/serialization failures. The quote metadata is synthetic;
quoting, venue-state validation, and live execution are not exercised. See
[transaction fixture provenance and regeneration](fixtures/transactions/README.md).

Add tests as behavior is implemented:

- Additional venue PDA and receipt fixtures.
- Vault and CLAMM quote math against their source fixtures.
- Venue graph alternatives, ranking before capping, and partial failures.
- No refresh, blockhash retrieval, or signing in the SDK.
- Browser/Node package imports and opt-in testnet routes.

All state-reading and quoting functions currently
throw `NotImplementedError`.
